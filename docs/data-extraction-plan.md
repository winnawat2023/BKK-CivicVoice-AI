# แผนการสำรวจและดึงข้อมูลจาก data.bangkok.go.th (BKK Open Data Portal)
**เป้าหมาย:** จัดเก็บข้อมูลย้อนหลังสูงสุด 3 ปี (ปี 2567, 2568, 2569 / ค.ศ. 2024–2026) เพื่อนำมาวิเคราะห์ปัญหาเชิงลึกของกรุงเทพมหานคร ก่อนนำไปสู่การออกแบบโซลูชัน

---

## 1. ผลการสำรวจเบื้องต้นของ data.bangkok.go.th

จากการยิงตรวจสอบผ่านระบบ CKAN API (`https://data.bangkok.go.th/api/3/action/`) พบข้อมูลสำคัญดังนี้:

* **ระบบที่ใช้งาน:** CKAN Open Data Platform พร้อม RESTful API รองรับการ query แบบอัตโนมัติ
* **จำนวนชุดข้อมูลทั้งหมด (Total Datasets):** **1,531 ชุดข้อมูล**
* **หน่วยงานเจ้าของข้อมูล (Organizations):** 118 องค์กร (ประกอบด้วย 50 สำนักงานเขต, สำนักการระบายน้ำ, สำนักการจราจรและขนส่ง, สำนักการโยธา ฯลฯ)
* **รูปแบบไฟล์หลัก:** `CSV`, `XLSX`, `PDF`, `DB (SQLite/Access)` และ `Google Drive / SharePoint Links`

---

## 2. การจัดกลุ่มชุดข้อมูลสำคัญ (ตามโจทย์ Hackathon & ปัญหาเมือง)

เพื่อตอบโจทย์การวิเคราะห์ปัญหาเมือง เราแบ่งข้อมูลที่ต้องดึงเป็น 4 กลุ่มหลัก:

### กลุ่มที่ 1: ข้อมูลเรื่องร้องเรียนและปัญหาเมืองโดยตรง (Core Civic Complaints) — *สำคัญสูงสุด*
1. **Traffy Fondue (ย้อนหลัง 3 ปี: 2567, 2568, 2569):**
   * ข้อมูลราย Record ของปัญหาที่ประชาชนแจ้งจริง พิกัด GPS, ประเภทปัญหา (ถนน, ทางเท้า, ขยะ, แสงสว่าง, น้ำท่วม, เสียงรบกวน), วันที่รับแจ้ง, หน่วยงานรับผิดชอบ, สถานะการแก้ไข, และระยะเวลาที่ใช้ในการปิดเคส
2. **สถิติการรับแจ้งเรื่องร้องเรียนผ่านสายด่วน 1555:**
   * สถิติและรายละเอียดเรื่องร้องเรียนผ่านช่องทาง Call Center 1555 และช่องทางอื่นๆ ของ กทม.

### กลุ่มที่ 2: โครงสร้างพื้นฐาน การจราจร และอุบัติเหตุ (Mobility & Safety)
* จุดเสี่ยงอุบัติเหตุทางถนน 100 จุดเสี่ยงใน กทม.
* สถิติอุบัติเหตุจราจรรายเขต/รายถนน
* ข้อมูลโครงข่ายขนส่งสาธารณะและจุดเชื่อมต่อ

### กลุ่มที่ 3: น้ำท่วม การระบายน้ำ และสิ่งแวดล้อม (Environment & Flood)
* จุดเสี่ยงน้ำท่วมขังบนถนนสายหลักและซอยย่อย (ปี 2567–2569)
* สถานีสูบน้ำ คลอง ประตูระบายน้ำ
* สถิติค่าฝุ่นละออง PM 2.5 และจุดความร้อน/มลพิษ

### กลุ่มที่ 4: ข้อมูลพื้นฐานเขตและประชากร (Demographics & Administrative)
* ข้อมูลประชากร ขอบเขต 50 สำนักงานเขต (Boundary & Population)
* ข้อมูลจุดบริการประชาชน และสิ่งอำนวยความสะดวกสาธารณะ

## 3. แผนการดึงข้อมูล 3 ขั้นตอน (Pipeline Architecture)

```
[ data.bangkok.go.th (CKAN API) ]
                 │
                 ▼
  Step 1: Metadata Harvesting & Indexing
  - รัน CKAN API ดึง Catalog ทั้ง 1,531 datasets
  - บันทึกลง catalog_index.json พร้อมจำแนก Format (CSV/Excel/Link)
                 │
                 ▼
  Step 2: Data Extraction & Downloader
  - Direct Download: ดึงไฟล์ CSV/XLSX ตรงจาก Server
  - Drive/SharePoint Handler: สคริปต์ดึงไฟล์ก้อนใหญ่ (Traffy Fondue 2567-2569)
  - Raw Storage: เก็บลง `data/raw/{category}/{year}/`
                 │
                 ▼
  Step 3: Data Cleaning, Standardization & Parquet/SQLite Store
  - แปลงวันที่ภาษาไทย (พ.ศ. -> ค.ศ.)
  - คลีนพิกัด ละติจูด/ลองจิจูด (Latitude / Longitude)
  - จัดหมวดหมู่ Standard Taxonomy (เช่น ประเภทปัญหา, เขต, หน่วยงาน)
  - บันทึกเป็น `data/processed/civic_issues_3years.parquet` หรือ `sqlite`
```

## 5. แผนการวิเคราะห์ปัญหาเมืองหลังได้ข้อมูลครบ (Problem Discovery Framework)

เมื่อดึงข้อมูล 3 ปีย้อนหลังครบ จะสามารถวิเคราะห์เชิงลึกได้ทันทีใน 4 มิติ:
1. **Trend & Volume Analysis:** แนวโน้มปัญหาเมืองที่พบบ่อยที่สุด 5 อันดับแรก (ทางเท้า, แสงสว่าง, ขยะ, น้ำท่วม, จราจร) ในรอบ 3 ปี ว่าปัญหาใดมีแนวโน้มเพิ่มขึ้นหรือลดลง
2. **Geographical Hotspots (Heatmap):** วิเคราะห์จุดกระจุกตัวของปัญหาตามเขต และถนนสายสำคัญ
3. **SLA & Resolution Bottlenecks:** วัดระยะเวลาเฉลี่ยในการแก้ปัญหาของแต่ละเขต/หน่วยงาน ปัญหาประเภทใดค้างท่อแก้ไขช้าที่สุด
4. **Root Cause Identification:** วิเคราะห์ความสัมพันธ์ระหว่างปัจจัยต่างๆ (เช่น ฝนตกหนักกับปัญหาน้ำท่วมและไฟดับ) เพื่อนำมาเป็นโจทย์ตั้งต้นในการสร้าง AI Solution ให้กับ กทม.
