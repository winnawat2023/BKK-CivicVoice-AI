   * ไฟล์ในคลังข้อมูลของโครงการ: [opendata/raw/complaints_1555/](../opendata/raw/complaints_1555/)

## 2. โครงสร้างการทำงานของสายด่วน 1555 (Current Operational Workflow)

* **หน่วยงานผู้รับผิดชอบ:** กองการร้องทุกข์ สำนักงานเลขานุการปลัดกรุงเทพมหานคร
* **เวลาให้บริการ:** ให้บริการ **ตลอด 24 ชั่วโมง (365 วัน ไม่มีวันหยุด)** โดยจัดเจ้าหน้าที่สลับผลัดหมุนเวียนรับสาย
* **หน้าที่หลัก 2 ด้าน:**
  1. **รับเรื่องร้องทุกข์และเหตุเดือดร้อนรำคาญ:** ปัญหาทางเท้า, ถนนพัง, ไฟฟ้าส่องสว่างดับ, ขยะตกค้าง, น้ำท่วม, ท่อระบายน้ำอุดตัน, เสียงรบกวน, หาบเร่แผงลอย
  2. **ให้ข้อมูลและตอบข้อซักถามบริการราชการ กทม.:** ตอบระเบียบขั้นตอนการทำบัตรประชาชน, ย้ายทะเบียนบ้าน, ภาษีที่ดินและสิ่งปลูกสร้าง, สิทธิเบี้ยยังชีพผู้สูงอายุ

### แผนผังกระบวนการทำงานในปัจจุบัน (Current Lifecycle):

```
[ ประชาชนโทรสายด่วน 1555 ]
            │
            ▼
[ ขั้นตอนที่ 1: เจ้าหน้าที่ Call Center รับสาย ]
  - สอบถามและรับฟัง: ปัญหาคืออะไร เกิดขึ้นที่ไหน (ระบุชื่อถนน/ซอย/จุดสังเกต)
  - คัดแยกว่าเป็น "เรื่องร้องทุกข์" หรือ "เพียงสอบถามข้อมูลราชการ"
            │
            ▼
[ ขั้นตอนที่ 2: บันทึกข้อมูลเข้าระบบ (Manual Data Entry) ]

  - เลือกว่าจะส่งต่อให้หน่วยงานใด (1 ใน 50 สำนักงานเขต หรือ สำนักเฉพาะทาง เช่น สำนักการโยธา/การระบายน้ำ/เทศกิจ)
  - ระบบออกรหัสคำร้อง (Tracking PIN) ส่ง SMS แจ้งประชาชนเพื่อใช้ติดตามสถานะ
            │
            ▼
[ ขั้นตอนที่ 3: การส่งต่อและประสานงาน (Dispatching) ]
  - เหตุฉุกเฉิน/อันตรายทันที (เช่น ฝาท่อเปิด, ต้นไม้ล้มขวางถนน): ประสานผ่านวิทยุสื่อสารหรือโทรแจ้งหน่วยฉุกเฉินเขตทันที
  - เรื่องทั่วไป: ส่งเข้าคิวงานของฝ่ายที่เกี่ยวข้องในสำนักงานเขต
            │
            ▼
[ ขั้นตอนที่ 4: การลงพื้นที่แก้ไขและปิดเคส ]
  - เจ้าหน้าที่เขตลงพื้นที่ตรวจสอบและอัปเดตสถานะในระบบ
```

## 3. ปัญหาและอุปสรรคสำคัญที่แท้จริง (Current Pain Points & Bottlenecks)

### 🔴 ปัญหาที่ 1: คู่สายเต็มและประชาชนต้องรอสายนาน (Queue Congestion)
* **ช่วงวิกฤต (ฝนตกหนัก น้ำท่วม ลมพายุ):** ประชาชนโทรเข้ามาพร้อมกันหลายร้อยสายต่อชั่วโมง ทำให้คู่สายเต็ม ประชาชนโทรไม่ติดหรือต้องรอสายนานกว่า 10–15 นาที
* **สายโทรสอบถามข้อมูลราชการทั่วไปกินเวลาคิว:** กว่า **30% – 40%** ของสายที่โทรเข้ามา ไม่ใช่การแจ้งเหตุเดือดร้อน แต่เป็นการ **"สอบถามข้อมูลระเบียบราชการ"** (เช่น ทำบัตรประชาชนวันเสาร์ได้ที่เขตไหน, ขั้นตอนขอใบอนุญาต) ซึ่งเจ้าหน้าที่ต้องใช้เวลาอธิบายทีละคน ทำให้บล็อกคิวของสายที่มีเหตุเดือดร้อนฉุกเฉิน

### 🔴 ปัญหาที่ 2: ความคลุมเครือของพิกัดจากเสียงพูด (Location Ambiguity)
* ในการแจ้งผ่านเสียง ประชาชนมักบอกจุดเกิดเหตุด้วย **"ภาษาพูดหรือจุดสังเกตส่วนตัว"** เช่น *"แถวๆ ร้านส้มตำป้าศรี หน้าปากซอยแคบๆ ลาดพร้าว"*
* ไม่มีพิกัด GPS อัตโนมัติเหมือนในแอป เจ้าหน้าที่ Call Center ต้องซักถามย้ำหลายรอบ หรือหากพิมพ์สรุปไม่ละเอียด เจ้าหน้าที่เขตภาคสนามลงพื้นที่จริงแล้วหาไม่เจอ ส่งผลให้เคสถูกตีกลับ (Reopen/Forward ไปมา)

### 🔴 ปัญหาที่ 3: ภาระงานเจ้าหน้าที่สูงและต้องพิมพ์ Manual (High Cognitive Load & Long AHT)
* เฉลี่ยเวลาสนทนาต่อสาย (Average Handling Time: AHT) อยู่ที่ 3–5 นาทีต่อสาย เพราะเจ้าหน้าที่ต้องทั้งฟัง ซักถาม พิมพ์สรุปข้อความ และเปิดคู่มือหาระเบียบราชการไปพร้อมกัน
* เจ้าหน้าที่ใหม่มักไม่แม่นยำเรื่องขอบเขตอำนาจหน้าที่ของแต่ละฝ่าย (เช่น ถนนสายนี้อยู่ในความรับผิดชอบของ กทม., กรมทางหลวงชนบท หรือการทางพิเศษ) ส่งผลให้ส่งเรื่องผิดหน่วยงานตั้งแต่ต้น

### 🔴 ปัญหาที่ 4: ประชาชนติดตามสถานะยากจนโทรซ้ำ (Repeat Calls)
* แม้ระบบจะส่ง SMS Tracking PIN ให้ แต่สำหรับประชาชนกลุ่มผู้สูงอายุหรือไม่เชี่ยวชาญสมาร์ทโฟน ไม่สามารถเข้าไปเปิดเว็บเช็คสถานะได้ จึงเลือกที่จะโทรกลับเข้ามาที่ 1555 ซ้ำๆ เพื่อสอบถามความคืบหน้า ทำให้เกิดภาระสายซ้ำซ้อนในระบบ

## 4. ตารางเปรียบเทียบ: จุดแข็ง-จุดอ่อน (1555 vs. Traffy Fondue)

| มิติการเปรียบเทียบ | สายด่วน 1555 (Voice Call) | Traffy Fondue (LINE / Application) |
| :--- | :--- | :--- |
| **กลุ่มผู้ใช้งานหลัก** | **ผู้สูงอายุ**, ประชาชนทั่วไป, คนขับรถ/กำลังเดินทาง | คนรุ่นใหม่, คนวัยทำงาน, ผู้ใช้สมาร์ทโฟนคล่อง |
| **ความสะดวกในการแจ้ง** | สะดวกที่สุด แค่ยกหูโทรออกแล้วพูดด้วยเสียงธรรมชาติ | ต้องพิมพ์ ถ่ายรูป และปักหมุดแผนที่ |
| **ความแม่นยำของพิกัด** | ⚠️ ต่ำ (อธิบายด้วยคำพูดและจุดสังเกต) | ✅ สูงมาก (ส่งพิกัด GPS จากเครื่องตรงๆ) |
| **ความเร็วในการรับเรื่อง** | ⚠️ ช้าเมื่อคู่สายเต็ม (ต้องรอคิวคนรับสาย) | ✅ ทันที (ระบบอัตโนมัติ 24 ชม.) |
| **การตอบคำถามราชการ** | ✅ มีเจ้าหน้าที่ตอบข้อซักถามได้ | ⚠️ ไม่ตอบคำถาม (เน้นรับเรื่องร้องเรียนเท่านั้น) |

## 5. การนำ Insight ไปออกแบบโซลูชัน BKK CivicConnect AI

จากปัญหาของสายด่วน 1555 คือโอกาสที่ **ARK Insights (ผู้เชี่ยวชาญด้าน Contact Center + Genesys Cloud CX + Thai LLM)** จะนำเสนอคุณค่าที่ตอบโจทย์คณะกรรมการ:

| ปัญหาเดิมของสายด่วน 1555 | BKK CivicConnect AI เข้ามาแก้อย่างไร | เทคโนโลยีที่ใช้ |
| :--- | :--- | :--- |
| **1. คู่สายเต็ม คนรอนาน** | **AI Voice Bot รับสายทันที 0 วินาที** คัดแยก Intent และตอบคำถามระเบียบ กทม. อัตโนมัติทันที | Genesys AudioHook + Typhoon/Gemma RAG |
| **2. พิกัดคลุมเครือ** | **Entity Extraction Engine** สกัดสถานที่ ชื่อถนน ซอย จุดสังเกต แปลงเป็นเขตและพิกัดแผนที่อัตโนมัติ | Fine-tuned LLM Prompt Extraction |
| **3. เจ้าหน้าที่เหนื่อยล้า (AHT นาน)** | **Genesys Agent Interaction Widget** แสดง Live Thai Transcript + สรุปประเด็น 3 บรรทัด + แนะนำขั้นตอนถัดไป (Next Best Action) ช่วยลด AHT ลง 50% | WebSocket + Custom Genesys iframe Widget |
| **4. โทรตามเรื่องซ้ำๆ** | **Caller ID Auto-Status Tracking** โทรกลับมาเบอร์เดิม AI ตรวจสอบเบอร์ผู้โทรและแจ้งความคืบหน้าของเรื่องที่เคยแจ้งได้ทันทีในสาย | Genesys ANI Inbound Lookup + Ticketing API |
