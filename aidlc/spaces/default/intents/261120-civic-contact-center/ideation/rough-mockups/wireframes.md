# Wireframes: BKK CivicConnect AI

อ้างอิง: `intent-statement.md` (Intent Capture), `scope-document.md` และ `intent-backlog.md` (Scope Definition) และคำตอบใน `rough-mockups-questions.md` ([Q<n>] คือหมายเลขคำถามในไฟล์นั้น) ข้อความในกรอบเป็นภาษาอังกฤษเพื่อให้กรอบจัดแนวได้ตรง ส่วนข้อมูลตัวอย่างอ้างอิงจากสถานการณ์ใน PRD ทั้งหมดนี้เป็นภาพร่างคร่าวๆ ไม่ใช่ดีไซน์สุดท้าย

หน้าจอทั้งหมดใช้สไตล์เรียบง่ายที่อ่านง่าย [Q8] ทำตามพื้นฐาน WCAG 2.1 AA [Q7] และรองรับคอมพิวเตอร์สำหรับเจ้าหน้าที่ และมือถือสำหรับประชาชน [Q6]

## หน้าจอ 1: Widget ของเจ้าหน้าที่ (Genesys Agent Workspace)

ใช้บนคอมพิวเตอร์ [Q1] [Q6] ส่วนบนสุดแสดงสรุป 3 ข้อ และข้อมูล Ticket ส่วนบทสนทนาสดอยู่ด้านล่างและเปิดดูเพิ่มได้ [Q3] [Q4] ปุ่มส่ง Ticket ต่อให้สำนักงานเขตเป็นส่วนเสริมที่ตัดได้ [scope-document.md]

```
+--------------------------------------------------------+
| AI Copilot                         Call 00:42   [Live] |
+--------------------------------------------------------+
| SUMMARY (3 key points)                                 |
|  1. Issue: broken drain, flooding                      |
|  2. Place: Sukhumvit 50, Khlong Toei                   |
|  3. Severity: HIGH                                     |
+--------------------------------------------------------+
| TICKET  BKK-2026-0001           Status: Received       |
| Category: Drainage   Agency: Khlong Toei District      |
| [ Send ticket to district office ]  (optional)         |
+--------------------------------------------------------+
| [v] Live transcript (open to read more)                |
+--------------------------------------------------------+
```

หมายเหตุการเข้าถึง: หัวข้อ h1 คือ "AI Copilot", หัวข้อ h2 คือ "Summary" และ "Ticket", landmark คือ main ที่ครอบทั้ง Widget, จุดเข้าด้วยแป้นพิมพ์คือปุ่มส่ง Ticket ต่อ แล้ววนไปปุ่มเปิดบทสนทนาสด

## หน้าจอ 2: รายการและรายละเอียด Ticket (เจ้าหน้าที่)

ใช้บนคอมพิวเตอร์ [Q1] [Q6] สถานะมี 3 ค่า คือ Received, In progress และ Resolved [Q9]

```
+--------------------------------------------------------+
| Tickets                        Filter: [All status v]  |
+--------------------------------------------------------+
| ID             Category    Place         Status        |
| BKK-2026-0001  Drainage    Khlong Toei   Received      |
| BKK-2026-0002  Sidewalk    Phaya Thai    In progress   |
| BKK-2026-0003  Lighting    Din Daeng     Resolved      |
+--------------------------------------------------------+
| Selected: BKK-2026-0002                                |
| Detail: broken tiles at the Soi Ari entrance           |
| Severity: Medium    Reporter notified: SMS sent        |
+--------------------------------------------------------+
```

หมายเหตุการเข้าถึง: หัวข้อ h1 คือ "Tickets", h2 คือ "Selected ticket", landmark คือ main และ region ของตาราง, จุดเข้าด้วยแป้นพิมพ์คือช่องตัวกรองสถานะ

## หน้าจอ 3: ตรวจสอบสถานะ Ticket (ประชาชน)

ใช้บนมือถือเป็นหลัก [Q1] [Q6] ประชาชนกรอก Ticket ID เพื่อดูสถานะ [Q1] [Q2]

```
+------------------------------------+
| Check ticket status                |
+------------------------------------+
| Ticket ID                          |
| [ BKK-2026-0002                  ] |
| [          Check status          ] |
+------------------------------------+
| Status: In progress                |
| Received --> In progress --> Done  |
|    [x]           [x]         [ ]   |
+------------------------------------+
```

หมายเหตุการเข้าถึง: หัวข้อ h1 คือ "Check ticket status", landmark คือ main, จุดเข้าด้วยแป้นพิมพ์คือช่อง Ticket ID และสถานะต้องมีข้อความกำกับ ไม่ใช้สีอย่างเดียว

## ข้อความแจ้งเตือนผู้แจ้ง

SMS ยังจำเป็นอยู่ (ต้องมี) ส่วนการแจ้งเตือนผ่าน LINE OA มีได้แต่ไม่จำเป็น [Q5] ตัวอย่างข้อความ SMS ที่ผู้แจ้งได้รับพร้อม Ticket ID:

- "Ticket BKK-2026-0002 received"

ตัวอย่างข้อความเมื่อสถานะเปลี่ยน (ผ่าน SMS หรือ LINE OA ซึ่งยังไม่ได้ตกลงขอบเขตในส่วนนี้ ดู Assumptions):

- "Ticket BKK-2026-0002 status: In progress"

## โครงสร้างข้อมูลและการจัดลำดับ (Information Architecture)

- หน้าจอเจ้าหน้าที่: Widget (สรุปและ Ticket ก่อน บทสนทนาสดตามหลัง) เชื่อมไปรายการ Ticket [Q3] [Q4]
- หน้าจอประชาชน: หน้าตรวจสอบสถานะหน้าเดียว [Q1]

## Assumptions & Open Questions

- คำตอบ Q5 ที่ให้ SMS ต้องมี ขัดกับ `scope-document.md` ที่จัดข้อความหรือ SMS ยืนยันเป็นส่วนมีก็ดีและตัดก่อนเป็นอันดับแรก ภาพร่างนี้ทำตามคำตอบ Q5 ล่าสุด และ `scope-document.md` ยังต้องปรับให้ตรงกัน [assumption]
- LINE OA เป็นการแจ้งเตือนขาออกที่มีได้แต่ไม่จำเป็น ซึ่งไม่ใช่ช่องทางรับเรื่องที่ `intent-statement.md` ตัดไว้นอกขอบเขต แต่ยังไม่ได้ยืนยันกับผู้ตัดสินขอบเขต [assumption]
- ยังไม่ได้ตกลงว่า SMS ที่ต้องมีครอบคลุมแค่ข้อความยืนยันตอนสร้าง Ticket หรือรวมการแจ้งเมื่อสถานะเปลี่ยนด้วย [assumption]
- ตัวอย่างข้อความแจ้งเตือนภาษาอังกฤษเป็นเพียงตัวอย่างโครงสร้าง ถ้อยคำจริงภาษาไทยยังไม่ได้กำหนด [assumption]
- ยังไม่ได้ตกลงว่า Ticket ที่ปิดแล้วจะแสดงต่อในรายการเจ้าหน้าที่นานเท่าใด [assumption]
