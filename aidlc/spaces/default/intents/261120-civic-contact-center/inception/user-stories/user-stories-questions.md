# User Stories — แผนและคำถามก่อนเขียนเรื่องราวผู้ใช้

> อ้างอิงจาก `requirements.md` (Requirements Analysis) และ `team-practices.md` ผู้ใช้และเรื่องหลักถูกกำหนดไว้แล้วในขั้นตอนก่อนหน้า คำถามนี้ถามเฉพาะวิธีเขียนเรื่องราวผู้ใช้ (user story) ที่ยังไม่ได้ตัดสิน เรื่องราวผู้ใช้ทุกเรื่องจะเขียนแบบ "ในฐานะ ... ฉันต้องการ ... เพื่อ ..." พร้อมเกณฑ์ผ่านแบบ Given/When/Then ตามกฎของขั้นตอน Inception และจัดลำดับความสำคัญแบบเดียวกับ `requirements.md`

## Q1. [เจ้าของผลิตภัณฑ์] ต้องเขียนเรื่องราวผู้ใช้ของใครบ้าง (select all that apply)

เหตุผลที่ถาม: ผู้ใช้ที่ยืนยันแล้วคือประชาชนและเจ้าหน้าที่ศูนย์ 1555 ส่วนสำนักงานเขตเป็นผู้มีส่วนได้ส่วนเสียที่ต้องการดูและปิดงาน Ticket

- A. ประชาชนผู้โทรเข้ามา (แจ้งปัญหา ถามข้อมูล และตรวจสอบสถานะ)
- B. เจ้าหน้าที่ศูนย์ 1555 (รับสายที่โอนมา ดูสรุป ดูและเปลี่ยนสถานะ Ticket)
- C. เจ้าหน้าที่สำนักงานเขต (รับ Ticket ที่ครบถ้วนและติดตามสถานะ)
- D. Not yet defined
- X. Other (please specify)

[Answer]: A, B, C

## Q2. [เจ้าของผลิตภัณฑ์] ควรจัดกลุ่มเรื่องราวผู้ใช้ตามอะไร

เหตุผลที่ถาม: การจัดกลุ่มกำหนดรหัสเรื่อง (US1.1, US1.2 ...) และลำดับการทำงานในขั้นตอนถัดไป

- A. ตามเส้นทางการใช้งาน (workflow) เช่น แจ้งปัญหาทางโทรศัพท์ ถามข้อมูลทางโทรศัพท์ ตรวจสอบสถานะ และเจ้าหน้าที่รับสายที่โอนมา
- B. ตามผู้ใช้ (persona) แล้วค่อยแตกเป็นเรื่อง
- C. ตามกลุ่มความต้องการ FR1 ถึง FR8
- D. Not yet defined
- X. Other (please specify)

[Answer]: X. Other (please specify) - จัดกลุ่มตาม role เช่น ประชาชน, เจ้าหน้าที่ศูนย์, เจ้าหน้าที่สำนักงานเขต

## Q3. [ทีมพัฒนา] เรื่องราวผู้ใช้ควรมีขนาดเท่าไร

เหตุผลที่ถาม: ทีมมีเวลาวันเดียว (ตาม `team-practices.md` ที่ใช้ TDD และสร้างชิ้นงานบางๆ ที่ทำงานครบทางก่อน) เรื่องที่ใหญ่เกินจะทดสอบและส่งมอบยาก

- A. เล็ก ทำและทดสอบเสร็จได้ภายในไม่กี่ชั่วโมง 1 เรื่องต่อ 1 ผลลัพธ์ที่ผู้ใช้เห็น
- B. ใหญ่ขึ้น 1 เรื่องต่อ 1 เส้นทางการใช้งานทั้งเส้น
- C. Not yet defined
- X. Other (please specify)

[Answer]: A

## Q4. [เจ้าของผลิตภัณฑ์] เรื่องที่ยังเป็นคำถามค้างจาก Requirements Analysis ควรเขียนอย่างไร

เหตุผลที่ถาม: คำถามค้างเช่นหัวข้อของการถามข้อมูลระเบียบ กทม. (FR5.3) และวิธีที่ประชาชนได้ Ticket ID เมื่อ SMS ส่งไม่ถึง ทำให้เขียนเกณฑ์ผ่านที่ตรวจได้ไม่ครบ

- A. เขียนเรื่องนั้นตามที่กำหนดแล้วเท่านั้น และบันทึกส่วนที่ยังไม่กำหนดเป็นคำถามค้างของเรื่อง ไม่เดาเกณฑ์
- B. ผมเสนอเกณฑ์เบื้องต้นที่สมเหตุสมผล (เช่น ถามข้อมูลทำบัตรประชาชน ขอทะเบียนบ้าน สิทธิการรักษา) ติดป้ายสมมติฐาน แล้วให้คุณยืนยันที่ขั้นตอนอนุมัติ
- C. Not yet defined
- X. Other (please specify)

[Answer]: A
