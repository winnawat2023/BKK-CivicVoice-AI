# Interaction Spec: BKK CivicConnect AI

อ้างอิง: `wireframes.md` และ `user-flow.md` (Rough Mockups), `stories.md` (User Stories), `requirements.md` (Requirements Analysis), `team-practices.md` (Practices Discovery), `mockups.md` และคำตอบใน `refined-mockups-questions.md` ([Q<n>] คือหมายเลขคำถามในไฟล์นั้น) รูปแบบข้อกำหนดของแต่ละส่วนประกอบตามแม่แบบ component-spec ของนักออกแบบ ข้อกำหนดนี้ไม่ระบุเทคโนโลยี เพราะภาษาและกรอบงานจะเลือกในขั้นตอนออกแบบ

## กฎร่วมของทุกหน้าจอ

- ทุกหน้าจอจัดการสถานะ โหลดอยู่, ไม่มีข้อมูล, เกิดข้อผิดพลาด, สำเร็จ [Q1]
- ข้อความบนหน้าจอเป็นภาษาไทยเป็นหลัก และมีภาษาอังกฤษกำกับ [Q2]
- ป้ายสถานะ Ticket มี 3 ค่า: รับเรื่องแล้ว (Received), กำลังดำเนินการ (In progress), แก้ไขเสร็จ (Resolved) และต้องมีข้อความกำกับเสมอ ไม่ใช้สีอย่างเดียว [Q2] [NFR2]
- การกระทำที่ส่งข้อมูล (ตรวจสอบสถานะ เปลี่ยนสถานะ ส่งต่อ) กดซ้ำไม่ได้ขณะรอผล เพื่อไม่ให้เกิดรายการซ้ำ [corner-checklist]
- ข้อมูลที่ผู้ใช้กรอกต้องไม่หายเมื่อเกิดข้อผิดพลาด [corner-checklist]
- Breakpoint: มือถือ (<768px) สำหรับหน้าตรวจสอบสถานะของประชาชน, คอมพิวเตอร์ (>1024px) สำหรับหน้าจอเจ้าหน้าที่ [RM Q6]

## ส่วนประกอบ

### StatusBadge (ป้ายสถานะ)

| Field | Value |
|---|---|
| Component | StatusBadge |
| Description | แสดงสถานะของ Ticket เป็นข้อความ |
| Category | display |

| State | Description | Trigger |
|---|---|---|
| default | แสดง รับเรื่องแล้ว / กำลังดำเนินการ / แก้ไขเสร็จ พร้อมข้อความภาษาอังกฤษกำกับ | มีสถานะ |
| unknown | แสดง "ไม่ทราบสถานะ" | ค่าสถานะอยู่นอก 3 ค่า |

- **Props:** `status` (รับเรื่องแล้ว, กำลังดำเนินการ, แก้ไขเสร็จ) จำเป็น
- **Accessibility:** ข้อความเป็นเนื้อหาจริง ไม่ใช่สีพื้น ความต่างสีไม่ต่ำกว่า 4.5:1 [NFR2]

### TicketIdForm (ฟอร์มกรอกหมายเลข Ticket)

| Field | Value |
|---|---|
| Component | TicketIdForm |
| Description | รับหมายเลข Ticket และส่งตรวจสถานะ |
| Category | input |

| State | Description | Trigger |
|---|---|---|
| default | ช่องว่าง พร้อมคำแนะนำ | โหลดหน้า |
| focus | ขอบช่องเห็นชัด | แป้น Tab หรือการแตะ |
| loading | ปุ่มแสดง "กำลังตรวจสอบ..." และกดซ้ำไม่ได้ | ส่งตรวจ |
| error-format | ข้อความที่ช่อง: หมายเลขต้องอยู่ในรูปแบบ BKK-2026-XXXX | รูปแบบไม่ถูกต้อง |
| error-not-found | "ไม่พบ Ticket หมายเลขนี้ ตรวจสอบแล้วกรอกใหม่" และคงข้อความที่กรอกไว้ | ไม่พบ Ticket |
| error-system | "ตรวจสอบไม่ได้ในขณะนี้ ลองใหม่อีกครั้ง" | ระบบผิดพลาด |

- **Props:** `value` (ข้อความ) ค่าตั้งต้นว่าง
- **Behavior:** ตรวจรูปแบบ `BKK-2026-XXXX` ก่อนส่ง [Q3] กด Enter ส่งได้เหมือนกดปุ่ม
- **Accessibility:** ช่องกรอกมีป้ายกำกับที่มองเห็นและผูกกับช่อง ข้อความผิดพลาดผูกกับช่องและโปรแกรมอ่านหน้าจออ่านทันที โฟกัสไปที่ช่องที่ผิดเมื่อเกิดข้อผิดพลาด

### StatusTimeline (เส้นสถานะ)

| Field | Value |
|---|---|
| Component | StatusTimeline |
| Description | แสดงลำดับ รับเรื่องแล้ว > กำลังดำเนินการ > แก้ไขเสร็จ และขั้นปัจจุบัน |
| Category | display |

- **States:** แต่ละขั้นเป็น เสร็จแล้ว, ขั้นปัจจุบัน หรือยังไม่ถึง และมีข้อความกำกับทุกขั้น
- **Responsive:** บนมือถือเรียงแนวตั้ง บนคอมพิวเตอร์เรียงแนวนอนได้
- **Accessibility:** เป็นรายการลำดับ (ordered list) ขั้นปัจจุบันมีข้อความ "ขั้นปัจจุบัน" ให้โปรแกรมอ่านหน้าจอ

### TicketTable (รายการ Ticket)

| Field | Value |
|---|---|
| Component | TicketTable |
| Description | รายการ Ticket พร้อมตัวกรองสถานะและเขต และเปิดรายละเอียด |
| Category | display / navigation |

| State | Description | Trigger |
|---|---|---|
| default | แถวของ Ticket พร้อมเวลาอัปเดตล่าสุด | โหลดสำเร็จ |
| loading | แถวโครงและข้อความ "กำลังโหลดรายการ Ticket..." | กำลังโหลด |
| empty | "ยังไม่มี Ticket" | ไม่มี Ticket ในระบบ |
| empty-filtered | "ไม่พบ Ticket ตามตัวกรองนี้" พร้อมปุ่มล้างตัวกรอง | กรองแล้วไม่พบ |
| error | "โหลดรายการไม่ได้" พร้อมปุ่มลองใหม่ และคงรายการเดิมพร้อมเวลาอัปเดตล่าสุด | โหลดไม่สำเร็จ |

- **Props:** `statusFilter`, `districtFilter` (ค่าตั้งต้น ทั้งหมด) [Q5]
- **Behavior:** เรียงตามเวลาที่แจ้งใหม่สุดก่อน ถ้าเวลาเท่ากันเรียงตามหมายเลข Ticket [corner-checklist] เลือกแถวแล้วเปิดรายละเอียด
- **Accessibility:** ใช้ตารางที่มีหัวคอลัมน์ แถวที่เลือกมีข้อความหรือสัญลักษณ์ ไม่ใช้สีอย่างเดียว ใช้แป้นลูกศรและ Enter เลือกแถวได้

### StatusChanger (ตัวเปลี่ยนสถานะ)

| Field | Value |
|---|---|
| Component | StatusChanger |
| Description | ให้เจ้าหน้าที่เปลี่ยนสถานะ Ticket ที่เลือก |
| Category | input |

| State | Description | Trigger |
|---|---|---|
| default | แสดงสถานะปัจจุบัน | เลือก Ticket |
| saving | ปิดการเปลี่ยนซ้ำ แสดง "กำลังบันทึก..." | กดเปลี่ยน |
| success | "เปลี่ยนสถานะเป็น <สถานะ> แล้ว" และสถานะบนหน้าจอเปลี่ยน | บันทึกสำเร็จ |
| error | "เปลี่ยนสถานะไม่สำเร็จ ลองใหม่" และสถานะเดิมไม่เปลี่ยน | บันทึกไม่สำเร็จ |

- **Behavior:** ยังไม่ได้กำหนดว่าย้อนสถานะกลับได้หรือไม่ (คำถามค้างจาก US2.2)
- **Accessibility:** ข้อความสำเร็จและผิดพลาดประกาศให้โปรแกรมอ่านหน้าจอ

### CopilotSummary (สรุปและข้อมูล Ticket ใน Widget)

| Field | Value |
|---|---|
| Component | CopilotSummary |
| Description | แสดงสรุป 3 ข้อ และข้อมูล Ticket ที่ส่วนบนสุดของ Widget |
| Category | display |

| State | Description | Trigger |
|---|---|---|
| default | สรุป 3 ข้อ และข้อมูล Ticket | สายโอนเข้าและมี Ticket |
| loading | "กำลังเตรียมข้อมูล..." | กำลังโหลด |
| empty | "ยังไม่มี Ticket สำหรับสายนี้" | สายโอนเข้าแต่ยังไม่มี Ticket |
| error | แถบ "โหลดสรุปไม่ได้" และยังแสดงข้อมูล Ticket | โหลดสรุปไม่ได้ |
| ticket-only | แสดงเฉพาะข้อมูล Ticket (ไม่มีสรุปและบทสนทนาสด) | ตัด AI Copilot [Q4] |

- **Accessibility:** การเปลี่ยนจากกำลังโหลดเป็นข้อมูลประกาศให้โปรแกรมอ่านหน้าจอ

### TranscriptPanel (บทสนทนาสด)

| Field | Value |
|---|---|
| Component | TranscriptPanel |
| Description | ส่วนพับสำหรับอ่านบทสนทนาสดภาษาไทย |
| Category | display |

- **States:** ปิด (ค่าตั้งต้น), เปิด, กำลังโหลด, ว่าง ("ยังไม่มีบทสนทนา"), ผิดพลาด ("แสดงบทสนทนาไม่ได้")
- **Behavior:** บทสนทนาแสดงชั่วคราวและไม่บันทึกลง Ticket [requirements.md FR2.5] (ยังเป็นคำถามค้างว่ากรณีนี้ยืนยันแล้วหรือไม่)
- **Accessibility:** ปุ่มเปิดปิดมีสถานะ expanded บอกโปรแกรมอ่านหน้าจอ ข้อความใหม่ไม่ขัดจังหวะการอ่านของเจ้าหน้าที่

### SendToDistrictButton (ส่งต่อให้สำนักงานเขต, ส่วนเสริม)

- **States:** default, disabled (เมื่อ Ticket ไม่มีเขต), saving, success ("ส่งต่อให้สำนักงานเขต <ชื่อเขต> แล้ว"), error ("ส่งต่อไม่สำเร็จ ลองใหม่")
- **Behavior:** ผลของการ "ส่งต่อ" ในต้นแบบยังไม่ได้กำหนด เพราะการเชื่อมระบบรับเรื่องจริงของ กทม. อยู่นอกขอบเขต [US2.5]

## ลำดับการใช้งานหลักตามเรื่อง

| เรื่อง | ลำดับโต้ตอบ | ส่วนประกอบ |
|---|---|---|
| US1.5 | กรอกหมายเลข > ตรวจสอบ > เห็นสถานะ หรือเห็นข้อความผิดพลาด | TicketIdForm, StatusBadge, StatusTimeline |
| US2.1 | เปิดรายการ > กรอง > เลือกแถว > ดูรายละเอียด | TicketTable |
| US2.2 | เลือก Ticket > เปลี่ยนสถานะ > เห็นผล | StatusChanger, StatusBadge |
| US2.3, US2.4 | สายโอนเข้า > เห็นสรุปและข้อมูล Ticket > เปิดบทสนทนาสด | CopilotSummary, TranscriptPanel |
| US2.5, US3.1 | กดส่งต่อ > เจ้าหน้าที่เขตเห็น Ticket ในรายการที่กรองตามเขต | SendToDistrictButton, TicketTable |

## Assumptions & Open Questions

- เวลาอัปเดตล่าสุดและปุ่มโหลดใหม่ในรายการ Ticket เป็นข้อเสนอ ยังไม่ได้กำหนดว่ารายการอัปเดตเองหรือไม่ [assumption]
- การเรียงลำดับรายการตามเวลาที่แจ้งใหม่สุดก่อนเป็นค่าที่ผมเลือก ไม่ได้มาจากคำตอบใดโดยตรง [assumption]
- การย้อนสถานะ Ticket และผลของการส่งต่อให้สำนักงานเขตในต้นแบบ ยังไม่ได้กำหนด
- ความต้องการที่ไม่ให้เก็บบทสนทนาลง Ticket (FR2.5) กับการแสดงบทสนทนาสดชั่วคราว ยังไม่ได้ยืนยัน
