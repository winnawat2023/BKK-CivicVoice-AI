# แผนเพิ่ม Tourist Assist: ซับคู่ภาษา + บทพูด + English Voice Assist

วันที่: 23 พฤศจิกายน 2026 (Asia/Bangkok)  
Branch: `feature/fe-widget`  
สถานะ: แผนเพิ่มเติมจาก `agent-copilot-tracking-plan-v2.md` ยังไม่ได้สร้างหรือทดสอบระบบแปล/TTS จริง

## 1. เป้าหมายและขอบเขต

ลดอุปสรรคภาษาระหว่างนักท่องเที่ยวที่พูดอังกฤษกับเจ้าหน้าที่ 1555 ที่ไม่ถนัดภาษาอังกฤษ โดยเพิ่มใน **Agent Copilot iframe 400–500px** ที่มีอยู่ ไม่สร้างหน้าจอแยกและไม่เปลี่ยน flow บันทึก/ส่งสำนักงานเขต

อ้างอิงบรีฟ `docs/design-brief-aitthiphon.md` §2 ที่ตรวจฉบับล่าสุดบน GitHub และคำสั่งผู้ใช้ ให้เพิ่ม 3 ความสามารถ:

1. **Real-time Dual Translation Subtitles:** ข้อความอังกฤษต้นฉบับและคำแปลไทยแสดงคู่กันในบทสนทนาเดียว
2. **AI Tourist Assist Script:** ประโยคภาษาอังกฤษสำหรับเจ้าหน้าที่ พร้อมความหมายไทยและคำอ่านไทยโดยประมาณ
3. **1-Click ให้ AI ตอบเสียงภาษาอังกฤษแทน:** เจ้าหน้าที่ตรวจ/เลือกข้อความแล้วกดให้ระบบส่งเสียงอังกฤษเข้าคู่สายจริง

รอบแรกรองรับไทย–อังกฤษตามบรีฟ เก็บภาษาจีนและภาษาอื่นเป็นงานต่อยอด ตัวเลขนักท่องเที่ยว 25–30 ล้านคน/ปีเป็นบริบทที่ผู้ใช้ให้มา หากนำลง pitch ต้องระบุปี แหล่งข้อมูล และนิยามผู้เยือนกรุงเทพฯ ให้ตรงก่อนใช้เป็นข้อเท็จจริง โดยไม่เหมารวมความสามารถภาษาอังกฤษของเจ้าหน้าที่ทุกคน

## 2. เพิ่มใน layout เดิมอย่างไร

- Header เพิ่มภาษาคู่สาย `EN → TH`, ตัวเลือกเปลี่ยนภาษาเมื่อระบบตรวจผิด และสถานะกำลังแปล/แปลไม่ได้
- Transcript แต่ละ segment แสดงป้ายผู้พูดและ timestamp ตามเดิม โดยแบ่งข้อความเป็น `EN · ต้นฉบับ` และ `TH · คำแปล` ใต้กัน ไม่แยกสองกล่องที่เลื่อนคนละจุด
- ข้อความ partial ใช้ตัวอักษรจางและระบุ “กำลังถอดเสียง”; คำแปลแสดง “กำลังแปล” จนผลพร้อม มี revision เพื่อแทนที่ segment เดิม ไม่เพิ่มบรรทัดซ้ำทุก token
- ชื่อเขต ถนน ซอย เลขที่ และจุดสังเกตต้องจับคู่กับต้นฉบับ เก็บชื่อเฉพาะ/ตัวเลขไว้ให้ตรวจ ไม่เปลี่ยนสถานที่โดยคาดเดาจากคำแปล
- AI Insight คงสรุป 3 ประเด็นภาษาไทยสำหรับเจ้าหน้าที่ พร้อมเปิดดูหลักฐานอังกฤษต้นทางได้ การแปลไม่ต้องสร้าง Ticket เพิ่ม
- เพิ่ม card **Tourist Assist** ระหว่าง Insight กับ Action Zone: ประโยคอังกฤษที่เลือก → ความหมายไทย → คำอ่านไทยโดยประมาณ → ปุ่มคัดลอก/แก้ไข/ฟังตัวอย่าง → ปุ่ม TTS ส่งเข้าคู่สาย
- แสดงเฉพาะสคริปต์ที่เลือกเต็มรูปแบบและพับตัวเลือกอื่น เพื่อไม่ให้ iframe แน่นเกินไป ปุ่ม dispatch ยังคงเป็น action หลักในการจัดการคำร้อง ส่วน TTS เป็น action ของบทสนทนา
- ถ้าภาษาเป็นไทยไม่แสดงพื้นที่ว่างของ English Assist; สามารถเปิดเองได้เมื่อจำเป็น ทุก state ตรวจที่ 380/400/450/500px และความสูง iframe ที่ใช้งานจริง

ภาพแนวคิดล่าสุด `designs/05-multilingual-agent-copilot-clean-pro.png` แสดง Copilot/Tracking พร้อม Dual Subtitles, Tourist Assist Script, คำอ่านไทย และปุ่ม English TTS แล้ว ใช้อ้างอิง layout/สี/ลำดับข้อมูล ไม่ใช่หลักฐานว่าระบบแปลหรือส่งเสียงเข้าคู่สายทำงานแล้ว

## 3. ตัวอย่างสคริปต์และกติกาการตอบ

ตัวอย่าง card สำหรับขอพิกัด (ต้องให้ผู้พูดภาษาอังกฤษตรวจข้อความ/คำอ่านก่อนใช้เดโม):

- **English:** “Could you tell me the street name and a nearby landmark?”
- **ความหมาย:** กรุณาบอกชื่อถนนและจุดสังเกตใกล้เคียง
- **คำอ่านโดยประมาณ:** คูด ยู เทล มี เดอะ สตรีต เนม แอนด์ อะ เนียร์บาย แลนด์มาร์ก

เตรียม template ก่อน: ทักทาย, ขอพูดซ้ำ/พูดช้า, ขอถนน/จุดสังเกต, ทวนรายละเอียด, ขอพิกัด/รูปผ่านลิงก์, แจ้งเลขเรื่อง และแจ้งขั้นตอนถัดไป ประโยคที่มีข้อมูลบริการต้องอิงชุดความรู้ที่ทีมเตรียมไว้ หรือสถานะที่ Backend ยืนยันแล้ว

กรณีไม่พบข้อมูลให้เสนอประโยคแจ้งว่าไม่มีข้อมูล/ขอตรวจสอบ ห้ามสร้างคำตอบระเบียบราชการเอง ไม่แปลง SLA คาดการณ์เป็นคำรับรองวันซ่อม ไม่บอกว่า “ส่งเรื่องแล้ว” ก่อน dispatch acknowledgement และไม่บอกว่า “ส่ง SMS แล้ว” ก่อนระบบตอบรับการส่งตามระดับจริง

คำอ่านไทยเป็นตัวช่วยมนุษย์อ่าน ไม่ใช่หลักฐานความถูกต้องของการออกเสียง และต้องไม่ถูกส่งเข้า English TTS ระบบส่งเฉพาะข้อความอังกฤษฉบับที่เจ้าหน้าที่เลือก/แก้ไขล่าสุด

## 4. เส้นทางข้อมูลและเจ้าของงาน

เสียงจาก Genesys → STT ถอดต้นฉบับพร้อมภาษา/ผู้พูด → Backend แปล EN เป็น TH → WS ส่งผลแบบจับคู่ segment → Widget แสดงซับ → AI สร้าง/เลือกบทตอบจากบริบทและข้อมูลเตรียมไว้ → เจ้าหน้าที่ตรวจ → TTS สร้างเสียงอังกฤษ → ระบบเสียงส่งเข้าคู่สาย → รับ playback status

- **Watchara:** แยกช่องเสียง/ผู้พูด, ยืนยันวิธีส่ง English TTS เข้าสายที่ active ผ่านเส้นทาง Genesys ที่รองรับ, หยุด/ยกเลิกเสียงและรับสถานะการเล่น
- **Peerapun:** STT multilingual, translation, script + คำอ่านไทย, grounded responses, TTS generation, contract/event และการควบคุมงานต่อสาย
- **Aitthiphon:** UI subtitle/script, ภาษา/state, reconnect, ปุ่มตรวจ/แก้/ส่ง TTS, ป้องกันกดซ้ำ/ข้อมูลผิดสาย และ simulator scenarios

ไม่ถือว่า Faster-Whisper ให้คำแปลไทยหรือแยกผู้พูดครบได้จากการถอดเสียงอังกฤษเพียงอย่างเดียว ต้องตรวจคุณสมบัติของ deployment และตกลง translation/diarization step แยกกับ Member 3 ก่อน ไม่มี API ส่งเสียงเข้าสายจริงใน Backend ตั้งต้น จึงต้องพิสูจน์ integration นี้ก่อนอ้างว่า TTS Assist พร้อม

## 5. Contract เสนอเพิ่มเติม

คง compatibility กับ `live_update` เดิม และเพิ่ม event/schema ผ่าน adapter หลังทีมตกลง ไม่เปลี่ยนทุก event เดิมโดยไม่มี version:

| กลุ่ม | ฟิลด์/พฤติกรรมที่ต้องมี |
|---|---|
| Dual subtitles | `interaction_id`, `segment_id`, `speaker`, `source_language`, `source_text`, `target_language`, `translated_text`, `is_final`, `revision`, `occurred_at`, `translation_status` |
| Entity highlights | ขอบเขตข้อความของแต่ละภาษาแยกกัน พร้อมประเภท/ค่าต้นทาง ไม่ใช้ตำแหน่งอักขระอังกฤษกับข้อความไทย |
| Tourist script | `script_id`, `revision`, `based_on_segment_id`, `english_text`, `thai_meaning`, `thai_pronunciation`, template/knowledge reference, ready/error state |
| TTS request | interaction ที่มีสิทธิ์ใช้งาน, script id/revision หรือข้อความอังกฤษที่ผ่านการตรวจ, language/voice ที่ทีมเลือก, `request_id`/idempotency key |
| TTS status | `request_id`, `interaction_id`, generating/ready/queued/playing/completed/cancelled/failed, error ที่แสดงให้เจ้าหน้าที่เข้าใจ |

ระบุ speaker อย่างน้อย agent/citizen และ tag เสียง AI ที่ระบบสร้างเพื่อไม่ให้ข้อความ/เสียงของบอตย้อนเข้ากระบวนการสร้างคำตอบแล้วพูดวน การใช้บอตพูดแทนมนุษย์ต้องไม่ถูกบันทึกเป็นคำพูดของประชาชน

ผลแปล/สคริปต์ที่อ้าง segment เก่าต้องมีการระบุว่าเก่าและขออัปเดต ก่อนส่ง TTS ให้ตรวจ active interaction และ script revision อีกครั้ง เมื่อเปลี่ยนสายหรือสายสิ้นสุดให้ยกเลิกงาน/ปิดปุ่มของสายเดิม

## 6. พฤติกรรมปุ่ม English TTS

1. เจ้าหน้าที่เลือก/ตรวจประโยคอังกฤษที่เห็นบน card แล้วกดปุ่มครั้งเดียว ถ้าแก้ข้อความแล้วให้ใช้ revision ใหม่
2. Widget ส่งคำขอผ่าน Backend พร้อม context และ idempotency; disable การส่งซ้ำขณะทำงาน
3. แสดงกำลังสร้างเสียง → พร้อม/รอส่ง → กำลังพูด → พูดจบ ตาม event จริง แสดงปุ่ม “หยุดเสียง” ระหว่างเล่น
4. ฝั่ง server อนุญาตเล่น TTS ทีละหนึ่งงานต่อคู่สาย ไม่ให้ซ้อนกัน หากระบบหลักกำลังพูดให้รอหรือปฏิเสธพร้อมเหตุผลตามนโยบายที่ทีมเลือก
5. การฟังตัวอย่างในเครื่องเจ้าหน้าที่และการส่งเสียงเข้าคู่สายเป็นคนละปุ่ม/สถานะ ไฟล์ audio หรือเสียงที่เล่นจาก iframe อย่างเดียวไม่ใช่หลักฐานว่านักท่องเที่ยวได้ยิน
6. ถ้า timeout หลังส่ง ห้ามเล่นซ้ำอัตโนมัติ ให้ตรวจ request status เดิมก่อน retry; retry การพูดใหม่ต้องเป็นความตั้งใจของเจ้าหน้าที่
7. ถ้าสายสิ้นสุด/เปลี่ยน interaction ให้ cancel และไม่ส่งเสียงค้างไปสายถัดไป; การยืนยัน play ไม่ใช่หลักฐานว่าคู่สายเข้าใจ จึงทดสอบจากเครื่องปลายทางด้วย

ถ้ายังต่อ media path ไม่ได้ ให้เดโม local preview พร้อมป้าย “ยังไม่ได้ส่งเข้าคู่สาย” และนับเป็นงานค้าง ไม่ใช้ข้อความ success ว่า AI พูดตอบผู้โทรแล้ว

## 7. ลำดับส่งมอบรวมกับแผนเดิม

| ลำดับ | งาน | เกณฑ์พร้อม |
|---|---|---|
| T0 | ตกลง schema และพิสูจน์ TTS เข้าสาย | เล่นประโยคอังกฤษที่เตรียมไว้ให้ผู้โทรทดสอบได้ยินจริงและหยุดได้; ทำก่อนขยายบทตอบ |
| T1 | Dual subtitle UI + mock EN/TH | ต้นฉบับ/คำแปลคู่กัน, partial/final ไม่ซ้ำ, เปลี่ยนสายแล้วไม่ปน |
| T2 | Script card + template | อังกฤษ/ความหมาย/คำอ่านตรงกัน, แก้ไขได้, สคริปต์นอกฐานข้อมูลไม่แต่งคำตอบ |
| T3 | ต่อ Backend/WS multilingual | ทดสอบสำเนียง เสียงรบกวน ชื่อเขตและถนน พร้อมแสดง state เมื่อแปลไม่ได้ |
| T4 | TTS end-to-end | ประโยคที่เลือกพูดเข้าคู่สายจริงครั้งเดียว ไม่เล่นซ้อนและไม่พูดวน |
| T5 | Regression + rehearsal | Thai flow, dispatch, SMS/Tracking/GPS เดิมยังทำงาน |

วันที่เสนอ: 24 พ.ย. T0/T1, 25 พ.ย. T2/T3, 26 พ.ย. T4 + ชุด fault, 27 พ.ย. prototype รวมพร้อมบทเดโม โดยทดสอบ media path ควบคู่ตั้งแต่ต้น ไม่เลื่อนไปทำครั้งแรกก่อนขึ้นเวที ส่วน feature ที่ยังไม่ผ่านต้องแสดงขอบเขตจริงให้ชัด

## 8. Acceptance และ Simulator

- นักท่องเที่ยวพูดอังกฤษ: Widget แสดงต้นฉบับและคำแปลไทยใน segment เดียวกัน พร้อม speaker และสถานะแปล
- ชื่อถนน/ซอย/เขตและเลขที่ไม่สูญหาย ไม่แปลชื่อสถานที่ไปเป็นอีกแห่ง; ถ้าไม่แน่ใจให้ขอทวน
- ลำดับ partial/final, event ซ้ำ, event มาช้า และ reconnect ไม่เพิ่มคำแปลซ้ำหรือย้อน revision
- เมื่อเปลี่ยนภาษา/เปลี่ยนสาย การแปลและสคริปต์เก่าไม่ทับของใหม่
- บทตอบมีอังกฤษ ความหมาย และคำอ่าน; ผู้ตรวจภาษาอังกฤษยืนยันความหมาย/ชื่อเฉพาะ ไม่ใช้โมเดลเดียวให้คะแนนตัวเองเป็นหลักฐานผ่าน
- คำถามที่ไม่มีในข้อมูล: แนะนำคำตอบว่าไม่ทราบ/ขอตรวจสอบแทนการแต่งข้อมูล และไม่สร้าง promise เรื่อง SLA/การส่งต่อ
- ปุ่ม TTS ส่งเฉพาะอังกฤษที่ตรวจแล้วครั้งเดียว; edit revision, double click, timeout, queue ซ้อน, cancel, hangup และ switch call มีผลตามข้อ 6
- ข้อความ TTS จากระบบไม่ถูกเข้าใจเป็นคำพูดประชาชนและไม่กระตุ้นการตอบวน
- ทดสอบได้ยินจากเครื่องผู้โทรจริง รวมเสียงขัดจังหวะ/การหยุด โดย HTTP/WS mock พิสูจน์เพียง UI/contract ไม่พิสูจน์ audio injection
- เพิ่ม simulator scenarios: `tourist_en`, `translation_failure`, `language_switch`, `stale_translation`, `tts_double_click`, `tts_timeout`, `tts_cancel`, `tts_call_ended`, `cross_call_isolation` (เป็นชื่อเสนอ ยังไม่รองรับในสคริปต์เดิม)

เก็บเวลาแยกจากผู้โทรพูดจบถึง transcript final, ถึงคำแปลพร้อม, ถึง script พร้อม และจากกด TTS ถึงเครื่องปลายทางเริ่มได้ยิน บันทึก hardware/model/network และรายงานจำนวนตัวอย่าง/ค่ากลาง/ช่วงช้า ไม่อ้างความเร็วหรือความแม่นยำที่ยังไม่ได้วัด
