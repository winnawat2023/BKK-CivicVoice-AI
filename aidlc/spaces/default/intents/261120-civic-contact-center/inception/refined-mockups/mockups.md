# Mockups: BKK CivicConnect AI

อ้างอิง: `wireframes.md` และ `user-flow.md` (Rough Mockups), `stories.md` (User Stories), `requirements.md` (Requirements Analysis), `team-practices.md` (Practices Discovery) และคำตอบใน `refined-mockups-questions.md` ([Q<n>] คือหมายเลขคำถามในไฟล์นั้น) เรื่องที่ตัดสินแล้วในขั้นตอนก่อนหน้า ได้แก่ หน้าจอ 3 หน้า คอมพิวเตอร์สำหรับเจ้าหน้าที่ มือถือสำหรับประชาชน WCAG 2.1 AA และสไตล์เรียบง่าย ถูกนำมาใช้ตามเดิม

กรอบ ASCII ใช้ป้ายภาษาอังกฤษสั้นๆ เพื่อให้กรอบจัดแนวตรง ข้อความจริงบนหน้าจอเป็นภาษาไทยเป็นหลักและมีภาษาอังกฤษกำกับ [Q2] ตามตารางข้อความใต้แต่ละกรอบ ข้อมูลตัวอย่างอ้างอิงจากสถานการณ์ใน PRD เป็นข้อมูลสมมติทั้งหมด

ป้ายสถานะ Ticket ที่ใช้ทุกหน้า: **รับเรื่องแล้ว (Received)**, **กำลังดำเนินการ (In progress)**, **แก้ไขเสร็จ (Resolved)** [Q2] ซึ่งแก้ความไม่ตรงกันของป้าย "Done" ในภาพร่างเดิม

Ticket ID ใช้รูปแบบ `BKK-2026-XXXX` ตามเดิม [Q3]

ทุกหน้าจอต้องจัดการสถานะ โหลดอยู่, ไม่มีข้อมูล, เกิดข้อผิดพลาด และสำเร็จ [Q1]

---

## หน้าจอ 1: Widget ของเจ้าหน้าที่ศูนย์ (Genesys Agent Workspace)

ใช้บนคอมพิวเตอร์ ตรงกับเรื่อง US2.3, US2.4, US2.5 [stories.md] ส่วนบนสุดแสดงสรุป 3 ข้อและข้อมูล Ticket ส่วนบทสนทนาสดเปิดดูเพิ่มได้

### 1.1 สำเร็จ (มี AI Copilot)

```
+--------------------------------------------------------+
| AI Copilot                         Call 00:42   [Live] |
+--------------------------------------------------------+
| SUMMARY                                                |
|  1. Issue                                              |
|  2. Place                                              |
|  3. Severity                                           |
+--------------------------------------------------------+
| TICKET  BKK-2026-0001           Status: Received       |
| Category: Drainage District: Khlong Toei HIGH          |
| [ Send to district office ]  (optional)                |
+--------------------------------------------------------+
| [v] Live transcript                                    |
+--------------------------------------------------------+
```

| ส่วนที่แสดง | ข้อความไทย | English | ที่มา |
|---|---|---|---|
| หัวข้อ | ผู้ช่วย AI | AI Copilot | [US2.3] |
| สรุป | สรุป 3 ข้อ: เรื่อง สถานที่ ความเร่งด่วน | Summary: Issue, Place, Severity | [US2.3] |
| Ticket | ประเภทปัญหา, เขต, ความเร่งด่วน (สูง/กลาง/ต่ำ) | Category, District, Severity (High/Medium/Low) | [US1.2] [Q1] |
| ปุ่ม | ส่งต่อให้สำนักงานเขต (ส่วนเสริม) | Send to district office | [US2.5] |
| ส่วนพับ | บทสนทนาสด | Live transcript | [US2.4] |

### 1.2 สภาพอื่นของ Widget (Q1)

- **กำลังโหลด:** ส่วนสรุปและ Ticket แสดงข้อความ "กำลังเตรียมข้อมูล..." และไม่มีปุ่มส่งต่อจนกว่าข้อมูลพร้อม
- **ไม่มีข้อมูล:** เมื่อสายโอนเข้ามาแต่ยังไม่มี Ticket ให้แสดง "ยังไม่มี Ticket สำหรับสายนี้" และเจ้าหน้าที่ยังรับสายต่อได้
- **เกิดข้อผิดพลาด:** ถ้าสรุปหรือบทสนทนาสดไม่แสดง ให้แสดงแถบ "โหลดสรุปไม่ได้" เจ้าหน้าที่ยังเห็นข้อมูล Ticket ตามเดิม (ตามเส้นทางใน `user-flow.md`)
- **ถ้าตัด AI Copilot [Q4]:** Widget เหลือเฉพาะส่วน Ticket ดังกรอบด้านล่าง ไม่มีสรุปและบทสนทนาสด

```
+--------------------------------------------------------+
| Ticket                             Call 00:42   [Live] |
+--------------------------------------------------------+
| TICKET  BKK-2026-0001           Status: Received       |
| Category: Drainage District: Khlong Toei HIGH          |
+--------------------------------------------------------+
```

## หน้าจอ 2: รายการและรายละเอียด Ticket (เจ้าหน้าที่ศูนย์และเจ้าหน้าที่เขต)

ใช้บนคอมพิวเตอร์ ตรงกับเรื่อง US2.1, US2.2, US3.1 [stories.md] เจ้าหน้าที่สำนักงานเขตใช้หน้านี้เดียวกัน โดยกรองตามเขต [Q5]

### 2.1 สำเร็จ

```
+--------------------------------------------------------+
| Tickets   Status [All v]   District [All v]   [Reload] |
+--------------------------------------------------------+
| ID             Category    District      Status        |
| BKK-2026-0001  Drainage    Khlong Toei   Received      |
| BKK-2026-0002  Sidewalk    Phaya Thai    In progress   |
| BKK-2026-0003  Other       Din Daeng     Resolved      |
+--------------------------------------------------------+
| Updated: 10:42                                         |
+--------------------------------------------------------+
| Selected: BKK-2026-0002                                |
| Summary: broken tiles at the Soi Ari entrance          |
| Severity: Medium     Change status: [ In progress v ]  |
+--------------------------------------------------------+
```

| ส่วนที่แสดง | ข้อความไทย | English | ที่มา |
|---|---|---|---|
| ตัวกรอง | สถานะ, เขต, โหลดใหม่ | Status, District, Reload | [US2.1] [US3.1] [Q5] |
| เวลาปรับปรุง | อัปเดตล่าสุด 10:42 | Updated 10:42 | [assumption] |
| ปุ่มเปลี่ยนสถานะ | เปลี่ยนสถานะ | Change status | [US2.2] |

### 2.2 สภาพอื่นของหน้ารายการ (Q1)

- **กำลังโหลด:** แสดงแถวโครงกำลังโหลด และข้อความ "กำลังโหลดรายการ Ticket..."
- **ไม่มีข้อมูล:** แสดง "ยังไม่มี Ticket" ถ้ากรองแล้วไม่พบ ให้แสดง "ไม่พบ Ticket ตามตัวกรองนี้" พร้อมปุ่มล้างตัวกรอง [US2.1 AC2.1.3]
- **เกิดข้อผิดพลาด:** แสดง "โหลดรายการไม่ได้" พร้อมปุ่มลองใหม่ รายการที่โหลดไว้ก่อนหน้ายังแสดงพร้อมเวลาปรับปรุงล่าสุด
- **เปลี่ยนสถานะสำเร็จหรือไม่สำเร็จ:** แสดงข้อความยืนยัน "เปลี่ยนสถานะเป็น กำลังดำเนินการ แล้ว" หรือ "เปลี่ยนสถานะไม่สำเร็จ ลองใหม่" โดยสถานะบนหน้าจอไม่เปลี่ยนจนกว่าจะสำเร็จ

## หน้าจอ 3: ตรวจสอบสถานะ Ticket (ประชาชน)

ใช้บนมือถือเป็นหลัก ตรงกับเรื่อง US1.5 [stories.md]

### 3.1 สำเร็จ

```
+------------------------------------+
| Check ticket status                |
+------------------------------------+
| Ticket ID                          |
| [ BKK-2026-0002                  ] |
| [          Check status          ] |
+------------------------------------+
| Status: In progress                |
| Received > In progress > Resolved  |
|    [x]           [x]          [ ]  |
+------------------------------------+
```

| ส่วนที่แสดง | ข้อความไทย | English | ที่มา |
|---|---|---|---|
| หัวข้อ | ตรวจสอบสถานะเรื่องที่แจ้ง | Check ticket status | [US1.5] |
| ช่องกรอก | หมายเลข Ticket (ตัวอย่าง BKK-2026-0002) | Ticket ID | [US1.5] [Q3] |
| ปุ่ม | ตรวจสอบสถานะ | Check status | [US1.5] |
| สถานะ | รับเรื่องแล้ว, กำลังดำเนินการ, แก้ไขเสร็จ | Received, In progress, Resolved | [Q2] |

### 3.2 สภาพอื่นของหน้าตรวจสอบสถานะ (Q1)

- **เริ่มต้น (ยังไม่กรอก):** ช่องว่าง พร้อมคำแนะนำ "กรอกหมายเลข Ticket ที่ได้รับทาง SMS"
- **กำลังโหลด:** ปุ่มแสดง "กำลังตรวจสอบ..." และกดซ้ำไม่ได้ เพื่อไม่ให้ส่งซ้ำ
- **ไม่พบ Ticket:** แสดง "ไม่พบ Ticket หมายเลขนี้ ตรวจสอบหมายเลขแล้วกรอกใหม่" และคงข้อความที่กรอกไว้ [US1.5 AC1.5.2]
- **รูปแบบหมายเลขไม่ถูกต้อง:** แสดง "หมายเลขต้องอยู่ในรูปแบบ BKK-2026-XXXX" ที่ช่องกรอก
- **เกิดข้อผิดพลาดของระบบ:** แสดง "ตรวจสอบไม่ได้ในขณะนี้ ลองใหม่อีกครั้ง"
- **ไม่ได้รับ SMS:** ยังไม่ได้กำหนดวิธีที่ประชาชนได้หมายเลข Ticket เมื่อ SMS ส่งไม่ถึง (คำถามค้างจาก Requirements Analysis)

## ข้อความ SMS (ต้องมี)

ตัวอย่างข้อความที่ประชาชนได้รับเมื่อสร้าง Ticket สำเร็จ [US1.4]: "รับเรื่องแล้ว หมายเลข BKK-2026-0002 ตรวจสอบสถานะได้ที่หน้าตรวจสอบสถานะ" ถ้อยคำสุดท้ายและที่อยู่หน้าเว็บยังไม่ได้กำหนด

## Assumptions & Open Questions

- เวลาปรับปรุงล่าสุดและปุ่มโหลดใหม่ในหน้ารายการ Ticket เป็นข้อเสนอของผม ไม่ได้มาจากคำตอบใดโดยตรง และไม่ได้กำหนดว่ารายการอัปเดตเองหรือไม่ [assumption]
- ข้อความไทยของทุกสถานะและข้อผิดพลาดเป็นร่างแรก ยังไม่ผ่านการยืนยันถ้อยคำ [assumption]
- วิธีที่ประชาชนได้หมายเลข Ticket เมื่อ SMS ส่งไม่ถึงยังไม่ได้กำหนด
- ตัวกรองเขตแสดงเฉพาะเขตที่มี Ticket เพราะฐานข้อมูลครบ 50 เขตอยู่นอกขอบเขต [assumption]
- การยอมรับความเสี่ยงการเดาหมายเลข Ticket (Q3) ใช้ได้เฉพาะการสาธิตที่ใช้ข้อมูลสมมติ ไม่ควรใช้กับข้อมูลจริงของประชาชน
