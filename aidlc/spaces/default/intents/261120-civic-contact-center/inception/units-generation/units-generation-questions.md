# Units Generation — คำถามเพื่อแบ่งงานเป็นหน่วยงาน (Unit)

> อ้างอิงจาก `components.md` และ `decisions.md` (Domain Design), `requirements.md` และ `stories.md` Unit คือกลุ่มงานที่สร้างและทดสอบได้ด้วยตัวเอง ขั้นตอนนี้กำหนดเพียงว่า Unit ใดพึ่งพา Unit ใด (โครงสร้าง) ส่วนลำดับการทำและเส้นทางสำคัญจะตัดสินในขั้นตอน Delivery Planning ทีมเลือกทำชิ้นงานบางๆ ที่ทำงานครบตั้งแต่ต้นจนจบก่อน (walking skeleton) ดังนั้น Unit แรกต้องเป็นชิ้นงานที่ทำงานครบทาง คือรับสาย สร้าง Ticket และเห็น Ticket ID [team-practices.md]

## Q1. [สถาปนิก] ควรแบ่ง Unit ตามอะไร

เหตุผลที่ถาม: Domain Design แบ่งเป็น 7 ส่วนประกอบ แต่ Unit แรกต้องรันได้ครบทางตามวิธีทำงานของทีม ซึ่งต้องใช้โค้ดจากหลายส่วนประกอบพร้อมกัน

**ตัวเลือก A: ตามส่วนประกอบ (1 ส่วนประกอบต่อ 1 Unit รวม 7 Unit)**
- ข้อดี: ขอบเขตชัด ตรงกับ Domain Design
- ข้อเสีย: Unit แรกรันครบทางไม่ได้เพราะแต่ละส่วนประกอบไม่ทำงานจนจบเพียงลำพัง และต้องรอหลาย Unit เสร็จจึงเห็นผลสาธิต
- ย้อนกลับ: รวมหรือแยก Unit ได้

**ตัวเลือก B: ตามชิ้นงานที่ผู้ใช้เห็น (แบ่งแนวตั้ง ตัดผ่านหลายส่วนประกอบ)**
- Unit แรก: สายเข้า สร้าง Ticket และเห็น Ticket ID (ใช้ CallChannel, Conversation และ TicketService ในรูปแบบเล็กที่สุด) แล้วเพิ่มชิ้นงานอื่นเป็น Unit ต่อมา เช่น หน้ารายการและตรวจสอบสถานะ, การแจ้ง SMS, ถามข้อมูลระเบียบ และ Widget เจ้าหน้าที่
- ข้อดี: Unit แรกตรงกับ walking skeleton และส่วนที่ตัดได้ (ถามข้อมูล, Widget, LINE OA) เป็น Unit ของตัวเอง ตัดได้โดยไม่กระทบ Unit อื่น
- ข้อเสีย: หลาย Unit แก้ส่วนประกอบเดียวกัน (เช่น Conversation) ต้องกำหนดสัญญาและลำดับพึ่งพาให้ชัด
- ย้อนกลับ: ปานกลาง เพราะโค้ดของส่วนประกอบเดียวกันกระจายหลาย Unit

**คำแนะนำ:** ตัวเลือก B เพราะวิธีทำงานของทีมกำหนดให้ Unit แรกรันครบทาง และ `scope-document.md` ระบุส่วนที่ตัดได้หลายชิ้น

- A. ตัวเลือก A (ตามส่วนประกอบ)
- B. ตัวเลือก B (ตามชิ้นงานที่ผู้ใช้เห็น)
- C. Not yet defined
- X. Other (please specify)

[Answer]: B
