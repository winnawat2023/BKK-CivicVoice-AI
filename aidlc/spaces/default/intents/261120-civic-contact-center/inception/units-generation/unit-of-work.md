## รายละเอียดของแต่ละ Unit

### U1 u1-call-to-ticket (service, L) — ชิ้นงานบางๆ ที่รันครบทาง

- **คำอธิบาย:** รับสายจริงจาก Genesys แยกประเภทสาย สกัดประเภทปัญหา สถานที่ และความเร่งด่วน สร้าง Ticket และออก Ticket ID เป็นชิ้นงานที่รันครบทางชิ้นแรกตามวิธีทำงานของทีม [team-practices.md]
- **ส่วนประกอบที่ใช้ (เฉพาะส่วนเล็กที่สุดที่ทำให้รันครบทาง):** CallChannel, Conversation (แจ้งปัญหาและสรุป 3 ข้อ) และ TicketService (สร้าง Ticket และออก ID)
- **เรื่องที่ครอบคลุม:** US1.1, US1.2
- **หน้าที่:** รับผิดชอบเส้นทางตั้งแต่สายเข้าจนได้ Ticket ID เป็นฐานที่ Unit อื่นต่อยอด
- **การติดตั้ง:** รวมอยู่ในชิ้นหลังบ้านเดียว [Q4]
- **ข้อจำกัด:** ต้องใช้ Genesys Cloud จริงทดสอบ (ไม่มีทางป้อนสายจำลองตาม ADR-006) ความเสี่ยงสูงสุดของโครงการอยู่ที่นี่ [raid-log.md]

### U2 u2-ask-back-and-transfer (service, M)

- **คำอธิบาย:** ถามกลับเรื่องสถานที่ 1 ครั้ง ถามซ้ำสูงสุด 2 ครั้งเมื่อไม่เข้าใจ แล้วโอนสายหาเจ้าหน้าที่ และถือว่าผลลัพธ์ AI ที่ผิดรูปแบบคือไม่เข้าใจ
- **ส่วนประกอบที่ใช้:** Conversation และ CallChannel
- **เรื่องที่ครอบคลุม:** US1.3, US1.7
- **การติดตั้ง:** รวมอยู่ในชิ้นหลังบ้านเดียว [Q4]
- **ข้อจำกัด:** นิยามของ "รูปแบบที่ตรวจสอบได้" ของผลลัพธ์ AI ยังไม่ชัด ต้องปิดใน Functional Design

### U3 u3-notifications (service, M)

- **คำอธิบาย:** ส่ง SMS แจ้ง Ticket ID ไปยังเบอร์ที่โทรเข้า (ต้องมี) โดยไม่เก็บเบอร์ และส่งผ่าน LINE OA เพิ่มได้ (ตัดได้)
- **ส่วนประกอบที่ใช้:** Notification และ Conversation (ส่วนสั่งส่ง)
- **เรื่องที่ครอบคลุม:** US1.4, US1.8
- **การติดตั้ง:** รวมอยู่ในชิ้นหลังบ้านเดียว [Q4]
- **ข้อจำกัด:** ช่องทางส่ง SMS ยังไม่ได้เลือก และ `scope-document.md` ยังจัด SMS เป็นส่วนที่ตัดได้ ซึ่งขัดกับ FR3 ที่เป็น Must ต้องปรับให้ตรงกัน ส่วน LINE OA ต้องการตัวระบุผู้ใช้ LINE ซึ่งยังไม่มีที่มา

### U4 u4-citizen-status (ui, S)

- **คำอธิบาย:** หน้าตรวจสอบสถานะ Ticket ด้วย Ticket ID สำหรับประชาชนบนมือถือ
- **ส่วนประกอบที่ใช้:** TicketWeb (ส่วนสำหรับประชาชน) และ TicketService (ส่วนอ่านสถานะ)
- **เรื่องที่ครอบคลุม:** US1.5
- **การติดตั้ง:** หน้าเว็บที่ให้บริการแยกออกมา [Q4]
- **ข้อจำกัด:** การป้องกันการเดา Ticket ID ยังไม่ตัดสิน (ยอมรับเฉพาะการสาธิต)

### U5 u5-staff-tickets (ui, M)

- **คำอธิบาย:** หน้ารายการและรายละเอียด Ticket สำหรับเจ้าหน้าที่ศูนย์และเจ้าหน้าที่เขต กรองตามสถานะและเขต เปลี่ยนสถานะ และความสามารถทำเครื่องหมายส่งต่อให้สำนักงานเขต
- **ส่วนประกอบที่ใช้:** TicketWeb (ส่วนสำหรับเจ้าหน้าที่) และ TicketService (รายการ เปลี่ยนสถานะ และส่งต่อ)
- **เรื่องที่ครอบคลุม:** US2.1, US2.2, US3.1 และส่วนที่ทำเครื่องหมายส่งต่อของ US2.5
- **การติดตั้ง:** หน้าเว็บที่ให้บริการแยกออกมา และส่วนหลังบ้านของ TicketService รวมในชิ้นหลังบ้านเดียว [Q4]
- **ข้อจำกัด:** ยังไม่ได้กำหนดผลของการ "ส่งต่อ" ในต้นแบบ และการย้อนสถานะ

### U6 u6-knowledge-answers (service, M)

- **คำอธิบาย:** ตอบคำถามข้อมูลระเบียบ กทม. เฉพาะจากชุดข้อมูลตัวอย่าง และบอกตรงๆ เมื่อไม่มีข้อมูล
- **ส่วนประกอบที่ใช้:** KnowledgeAnswer และ Conversation (ส่วนเรียกใช้)
- **เรื่องที่ครอบคลุม:** US1.6
- **การติดตั้ง:** รวมอยู่ในชิ้นหลังบ้านเดียว [Q4]
- **ข้อจำกัด:** ตัดได้เป็นอันดับที่ 2 เมื่อเวลาไม่พอ และหัวข้อของชุดข้อมูลยังไม่กำหนด

### U7 u7-agent-widget (ui, L)

- **คำอธิบาย:** Widget ที่ฝังใน Genesys Agent Workspace แสดงสรุป 3 ข้อ ข้อมูล Ticket บทสนทนาสด และปุ่มส่งต่อให้สำนักงานเขต
- **ส่วนประกอบที่ใช้:** AgentWidget, Conversation (ส่วนผลักข้อมูล) และ TicketService (อ่านข้อมูลและสั่งส่งต่อ)
- **เรื่องที่ครอบคลุม:** US2.3, US2.4, US2.5
- **การติดตั้ง:** หน้าเว็บที่ให้บริการแยกออกมาและต้องเข้าถึงได้จาก Genesys [Q4]
- **ข้อจำกัด:** เป็นส่วนมีก็ดี ตัดได้ ถ้าตัด Widget ต้องตัดฉากสาธิตหน้าจอเจ้าหน้าที่และตัวชี้วัด AHT ตามไปด้วย [scope-document.md] บทสนทนาสดไม่ถูกเก็บลง Ticket

## Assumptions & Open Questions

- ขนาดของแต่ละ Unit (S, M, L) เป็นการประเมินแบบระมัดระวัง ยังไม่ได้วัด [assumption]
- การย้ายความสามารถทำเครื่องหมายส่งต่อให้สำนักงานเขตไปไว้ที่ U5 เป็นการตัดสินใจของผมเพื่อให้ U5 ไม่ต้องรอ Widget ที่ตัดได้ อยู่ในแผนที่คุณอนุมัติแล้ว และตรงกับข้อสังเกต R-03 ของ Domain Design
- ความขัดแย้งเรื่อง SMS ระหว่าง `scope-document.md` (Could) กับ `requirements.md` (Must) ยังไม่ปิด และกระทบการจัดลำดับ U3 ใน Delivery Planning
- หัวข้อของชุดข้อมูลระเบียบ กทม. (U6) ยังไม่กำหนด
- ตัวระบุผู้ใช้ LINE ของ LINE OA (U3) ยังไม่มีที่มา
